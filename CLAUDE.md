## Architecture

Six independently-deployed pieces live in this repo. Pushing to `main` deploys only the first; the others each have their own deploy step, and a change spanning them must ship in dependency order (the Worker mints the JWT the artifact service authorises against, so the Worker goes first). For posts that means **deploy the Worker before the site**: the editor's Author list (`GET /api/users/names`) and citation lookup (`POST /api/citations/lookup`) call routes the old Worker does not have, and the top bar's post count needs `GET /api/posts?pending=1`:

1. **Next.js static site** (repo root) — statically exported at build time, hosted on **Cloudflare Pages** behind the custom domain. Cloudflare builds it directly from this GitHub repo (Pages Git integration); there is no GitHub Actions deploy workflow. All content is read from the repo (and the resume from Notion) **at build time**; there is no runtime server for the site itself.

   Migrated off GitHub Pages on 2026-08-15 after its origin certificate expired and could not renew: the ACME challenge runs through the Cloudflare-proxied apex, and Full (strict) refused the very certificate the renewal existed to replace. Cloudflare Pages has no origin certificate, so that whole failure mode is gone rather than managed.
2. **`worker/`** — a Cloudflare Worker (`mncoleman-admin-auth`) that handles admin login (Telegram OIDC), mints session JWTs, stores admin users in KV, fires **Cloudflare Pages deploy-hook** rebuilds (on a `scheduled()` cron trigger and from the admin panel), and proxies artifact uploads to the artifact service. It holds `GITHUB_TOKEN` for committing `data/artifacts.json`, `data/posts/*.md`, the `data/*.json` collections and `public/collections/` images; those commits are what trigger Pages builds. It also keeps blog drafts in the `POST_DRAFTS` KV namespace and the CalVer build counter in KV.
3. **`worker-mcp/`** — a second Cloudflare Worker (`mncoleman-site-mcp`) serving the **public, unauthenticated MCP server** at `https://mncoleman.com/mcp`. It owns a route on the Cloudflare-proxied apex, so `/mcp*` is intercepted while every other path still falls through to Cloudflare Pages. Worker routes take precedence over a Pages custom domain on the same hostname — verified empirically on a throwaway subdomain before the cutover, not assumed from docs. Also serves `/.well-known/mcp.json`. Holds no secrets; the public endpoint reads `public/data/site-content.json` (built by `scripts/generate-search-index.ts`, gitignored) plus the artifact service's public list endpoints. Stateless per MCP 2026-07-28 (SEP-2575) with the legacy `initialize` handshake still supported. Separate Worker on purpose — `worker/` gates every POST behind an Origin allowlist + CSRF header that MCP clients cannot send. It also serves the **signed-in endpoint `/mcp/admin`** (same tools plus admin ones: instant artifacts, AI library, post drafts), which always requires an OAuth bearer token. The authorization server is the admin Worker (`worker/mcp-oauth.ts`: `/oauth/register`, `/oauth/authorize`, `/oauth/token`); this Worker only forwards the caller's token to it over the `ADMIN` service binding, so it still holds no secret. **Deploy `worker/` before `worker-mcp/`**: the binding and the routes the tools call live there.
4. **`worker-www-redirect/`** — a third Cloudflare Worker (`mncoleman-www-redirect`) doing nothing but a `www` -> apex 301. Holds no secrets and reads nothing. It exists because GitHub Pages used to issue that redirect for free and a Pages custom domain does not — see the Gotchas.
5. **`server/`** — a Bun + Hono service on an Oracle ARM box (`artifacts.mncoleman.com`) that hosts uploaded artifacts (HTML/PDF/images, with visibility/password, edit mode and Claude linking backed by a SQLite notes DB) and the AI library (prompts + skills), each with auto-generated OG share images. Deployed as a Docker container. See `server/README.md`.
6. **`worker-tokens/`** — a fourth Cloudflare Worker (`mncoleman-token-count`) owning the route `mncoleman.com/api/count-tokens`. It holds `ANTHROPIC_API_KEY` and exposes only `POST /v1/messages/count_tokens` (model allowlist, per-IP rate limit, `MAX_CHARS` cap) so the static Skill Lens artifact can show real token counts without the key reaching a browser. Separate from `worker/` for the same Origin/CSRF reason as `worker-mcp/`.

Only the **resume** still comes from Notion (`lib/notion.ts` / `lib/resume.ts`: credentials validated before connect, sample data when absent, rethrow when present-but-failed; see Patterns). **Blog posts** are `data/posts/<slug>.md` (`lib/posts.ts`, with `lib/blog.ts` as the adapter the pages use); `lib/resources.ts` and `lib/projects.ts` read `data/*.json`.

## Key Files

- `app/layout.tsx` — Root layout: sticky header nav, footer, theme/transition providers, lazy GA, local Roboto font.
- `app/page.tsx` — Home page: bento grid + lazy theme-aware backdrop + animated icons.
- `components/home-backdrop.tsx` — Picks the backdrop per theme: Dark Veil (WebGL) in dark, `paper-backdrop.tsx` in light. Only the active theme's module is fetched.
- `components/paper-backdrop.tsx` — Light mode's ground: a procedural paper grain you can draw graphite on with the pointer. Not persisted. Clicking bare paper cycles the pencil through a muted rainbow (gated on the event target, since the canvas is `pointer-events-none` and the listener must live on the window). The eraser retraces the recorded strokes over 3s, clearing each line along its own path; the wipe repaints paper + grain along a swath **at the identity transform** — `destination-out` would punch through to the page background, and a pattern painted under the dpr transform seams against the untouched sheet.
- `scripts/generate-build-info.ts` + `lib/build-info.ts` — The build stamp behind the footer version line and the metrics dialog, written to the gitignored `data/build-info.json` before every `next build` and `next dev`. Line/file counts come from `git ls-files` (works in a shallow clone, because the checkout is always complete); commit history comes from `git log`, falling back to the **GitHub API** when the clone IS shallow, since one visible commit would make every average nonsense. **Nothing in it may fail the build** — every section degrades to `null` and the UI hides what it lacks.
- `components/site-version.tsx` + `components/site-metrics-dialog.tsx` + `components/ui/count-up.tsx` — The footer's `vN · sha · building since` line and the dialog behind it. Git figures are baked in; visitor averages are fetched live on first open (never on mount) from the Worker; elapsed days are computed on render, or "days since the first commit" would be wrong for everyone visiting between two deploys. `CountUp` carries a `setTimeout` **settle** alongside its rAF: a backgrounded tab pauses rAF outright, so a counter started in one would otherwise sit at zero forever and read as broken data.
- `lib/pencil.ts` — The paper-and-pencil engine (grain, smoothed multiply strokes, swath wipe, erase routing), shared by `components/paper-backdrop.tsx` and the brand kit's `PencilDemo`. Extracted rather than duplicated for the same reason the two OG renderers are a documented hazard: a brand kit whose demo has drifted from the thing it documents is worse than no demo.
- `components/selection-ink.tsx` — Mounted in the root layout, renders nothing. Recolours the text-selection highlight through the pencil's palette: a new colour on every new highlight, and a click *inside* a live selection re-rolls it in place (a `mousedown` `preventDefault` is what stops the click collapsing it first). Advances only on the empty→non-empty transition, because `selectionchange` fires continuously while dragging. Carries a second, lifted palette for dark mode — the same tint needs more contrast on a near-black ground, which is also why the alpha differs per theme. Publishes `--selection-ink`; `::selection` in `globals.css` reads it.
- `lib/click-sound.ts` + `components/click-sound.tsx` + `components/sound-toggle.tsx` — Every clickable thing makes a mechanical-keyboard sound, randomised per click rather than per element. `public/sounds/keys.wav` is a sprite of 14 presses on a fixed 190ms grid (cut from the CherryMX Black Mechvibes pack the Aceternity keyboard component uses), so the player needs a slice index and no offset table. It is **PCM on purpose** — a lossy codec prepends priming samples and shifts every slice off its slot. Bytes are prefetched on an idle callback and decoded through an `OfflineAudioContext`, which carries no autoplay policy, so the live `AudioContext` is only built inside the first real gesture and the first click is already audible. The listener is one passive *capture* `pointerdown` on the document (capture, so a component that stops propagation cannot silence its own button) plus `keydown` filtered to Enter/Space; `click` is deliberately not listened to, or Enter on a button would double-fire. Because it runs in the capture phase it must never throw — a `keydown` with nothing focused targets the *Document*, which has no `closest`, and an unguarded cast there took out every other keydown handler on the page. Opt in with `data-click-sound`, out with `data-click-sound="off"`, and `data-click-sound-typing` makes a field sound on every keystroke (only the site search has it — a form you have to fill in is not the place for this). The toggle is the right-most square of the corner cluster and, unlike the rest of it, is not `hidden md:`: the sound plays on a phone, so its switch has to be reachable there.
- `public/sounds/switch.wav` + `scripts/generate-switch-sound.py` — The pull chain's own snap, played by `components/pull-chain-toggle.tsx` (which also carries `data-click-sound="off"`, or the lamp would click twice). **Synthesised, not recorded**: every free light-switch sample carries an attribution requirement, and building it meant the chain jingle could be modelled explicitly — the detent, the stop ~15ms later, then three to five quiet links settling, which is the part that makes it read as a chain rather than a button. The generator is committed because it is the asset's only source; it is not part of the build, needs numpy, and is seeded so a re-run reproduces the file exactly. Every route into the toggle (chain pull, bulb click, screen-reader button) goes through the one `toggleRef`, so the sound cannot end up on only some of them.
- `components/blank-canvas-toggle.tsx` — Strips the homepage to its backdrop (the cards), keeping nav and the corner cluster. One class on `<html>` plus a couple of rules in `globals.css`; nothing else knows the mode exists and the sections stay mounted, so leaving it does not replay every entrance. `main` is floored at `100vh` in the mode — without it everything above the footer collapses and the footer rides up under the header. Not persisted. Corner cluster order is now sound `right-5` (all sizes) · cursor `right-[4.5rem]` · scroll `right-[8rem]` · blank canvas `right-[11.5rem]` · eraser `right-[15rem]` (light only, so the rest stay contiguous in dark).

## Data Model

Content is in git, edited from the admin panel (`/admin/posts`, `/admin/projects`, `/admin/resources`); only the resume page is still read from Notion. Projects and resources use **keyed tags** (`tags: { Tech: [...] }`, see `lib/tags.ts`); old records with a flat `tech`/`categories` array still load:

- **Blog posts** (`data/posts/<slug>.md`) — front matter {title, slug, date, tags, published, featured, excerpt, author, ogImage?} + Markdown body. Featured first, then newest-first. Moved off Notion; the one-time `scripts/import-notion-posts.ts` seeded them (already run; `data/posts/` is committed, and a missing directory fails a production build by design). `/admin/posts` autosaves drafts to the Worker's `POST_DRAFTS` KV (never a commit) and mirrors them in localStorage; **Publish** is the only commit (sha-locked, `slug_taken`/`stale` -> 409) and the commit triggers the Pages build. Two ways to publish: the editor's **Publish changes** commits just that post with its Status respected, and the top bar's global **Publish** commits every pending post along with projects/resources. A post is pending when its `POST_DRAFTS` draft differs from the committed file (`GET /api/posts?pending=1`, 20 per page to stay under the Free plan's 50 subrequests; it compares server-side, skips unchanged files by blob sha, and the admin refreshes it on navigation, focus (max once a minute), menu open and after publish, never per autosave; removal is not staged, delete is immediate). **Privacy:** the repo is public and drafts are not, so global Publish commits a pending post only if it already has a committed file or its Status is Published. A never-committed Draft stays in KV (listed in the menu as kept private, not counted) and is committed only by that post's own Publish changes. A committed post set to Draft is written but stays hidden; the slug locks once the file exists, whatever its Status.
- **Verse mentions + `/bible`** — a `/bible/<book>/<chapter>#v<n>` link in a post, project or resource body renders as a hover/tap verse card with the text baked in at build time (`components/bible/MarkdownLink.tsx`, `lib/bible-server.ts`; `components/collection-detail.tsx` takes it as the `anchor` prop so the admin preview bundle stays free of `fs`). Texts (KJV, WEB, public domain) are `public/bible-data/` (`NOTES.md` there records the WEB-to-KJV verse mapping, `LICENSES.md` the sources), cross-references `data/bible/xrefs` (OpenBible.info, CC BY 4.0, trimmed to the top 8 per verse; the chapter-page footer says so). Rebuild them with `scripts/bible/*`.
- **Resources** (`data/resources.json`) — id (slug), name, url, description, tags, published, content (markdown body). Edited at `/admin/resources`; Publish is a Worker-made commit that Pages builds. Moved off Notion on 2026-09-18 because every build fetched every page body and sat in rate-limit backoff for minutes.
- **Projects** (`data/projects.json`) — id (slug), name, description, url, tags, date, published, content. Same editor and flow as resources (`/admin/projects`); both share `components/admin/CollectionList.tsx` and `CollectionEditor.tsx`. Project and resource images are committed under `public/collections/`. Detail slugs derive from `slugify(name)`; `id` mirrors it, and renaming a record moves its page.
- **Resume page** (`NOTION_RESUME_PAGE_ID`) — single page, body rendered to markdown.
- **About page** — `data/about.json`, edited by hand in git (`components/admin/ContentEditor.tsx` is an orphaned About editor that no route mounts).
- **Artifacts** — static ones in `data/artifacts.json`; dynamic ("instant") ones served live from the artifact service (`source: 'static' | 'dynamic'`).
- **Search index** — `data/search-index.json` (gitignored), regenerated at build time from all content; the same script writes `public/data/site-content.json` (gitignored), the MCP Worker's feed.

## Patterns & Conventions

- **Credential validation before connect** (Notion fetchers, now the resume only): every Notion fetcher checks for a missing/placeholder token *before* calling `getNotionClient()`, and treats the two failure modes differently:
  1. **Credentials missing or placeholder** → return sample data. Local dev has to work with no `.env`.
  2. **Credentials present but the fetch failed** → rethrow, and let the build fail.

  Case 2 is deliberate: the site rebuilds daily and deploys unconditionally on success, so falling back to sample data during a Notion outage would publish "Welcome to Notion CMS" over the live site. A failed build leaves the previous good deploy live on Pages. `scripts/generate-search-index.ts` `process.exit(1)`s on the same throw, so the MCP feed can't drift either.

  ```typescript
  const token = process.env.NOTION_TOKEN;
  if (!databaseId || !token || token === 'ntn_your_integration_token_here') {
      console.warn('Returning sample data because Notion credentials are not configured');
      return [/* sample data */];
  }
  try {
      /* ...query Notion... */
  } catch (error) {
      console.error('Error fetching …:', error);
      throw error; // configured creds + failed fetch = outage, not a dev machine
  }
  ```

- **Static params from the data layer**: `[slug]` routes call `generateStaticParams` backed by `get*Slugs()` helpers; slugs are computed with `slugify()`/`artifactSlug()` from `lib/utils.ts` so build-time and client-side links always match.
- **No visible scrollbars, anywhere**: `app/globals.css` hides them on every element (`scrollbar-width: none` plus `*::-webkit-scrollbar`), covering the page, dropdowns, drawers, the editor and code blocks. Scrolling still works. Do not add scrollbar styling, `overflow` utilities meant to show a bar, or a scroll library UI. New scroll containers need nothing extra, except `data-lenis-prevent` (see Smooth scroll) so wheel events reach them. The same rule applies to mockups.
- **Popovers always portal and collision-flip; never rely on a container that can clip.** `components/ui/popover.tsx` is the one wrapper: Radix portal to the document root, `collisionPadding` 8px, `max-height: var(--radix-popover-content-available-height)` with an inner hidden-scrollbar scroller (`data-lenis-prevent`), and `z-[100]` (above dialogs 50, the Properties drawer 55, the shell 45). Dropdowns, date pickers, comboboxes and tooltips use it (or `SelectField` / `SelectMenu`, which sit on it), never an absolutely-positioned child of an `overflow` / `transform` ancestor. Caps on inner lists must use the available-height variable, not a fixed `max-h`.
- **Admin layout kit** (`components/admin/kit/`, barrel `index.ts`): every admin section is the Posts pattern: `PageHeader` (title, `SearchField` with `/`, `SegmentedFilter`, `SelectMenu` filters, one `NewButton`), a bordered `DataList` (`ColumnHeader`, `DataRow`, `RowTitle`, `Cell`, `StatusPill`, `Chip`), `ListFooter`, `EmptyState`/`ListSkeleton`, a per-row `RowAction` (Copy link; `useCopyLink` + `notify` toast), `useListKeyboard`, and a full-page editor with `usePropertiesDrawer` + `PropertiesDrawer`/`PropRow` (Cmd+. toggle, localStorage open state, modal below 768px). `Section`/`StatTile` are for dashboards. Pure logic (search/filter, copy-link URLs, drawer state) is in `list-logic.ts` / `copy-link.ts` / `drawer-state.ts`; `npx tsx components/admin/kit/kit.selftest.ts`. A `PropRow` label column is fixed and never overlaps its value; long free-text values use `stack`.
- **Frosted glass over Dark Veil**: `bg-background/40 backdrop-blur-xl border border-border/30`.
- **Lazy-load heavy/decorative code**: Dark Veil (OGL) and ScrollFloat (GSAP) are `dynamic(..., { ssr: false })` so they stay off the homepage's initial JS and don't affect LCP.
- **Smooth scroll**: `components/smooth-scroll.tsx` mounts one site-wide Lenis (`<ReactLenis root>`) in the root layout. It scrolls the real document, so `sticky`/`fixed` and `window.scrollY` readers are unaffected — but **every nested scroll container needs `data-lenis-prevent`** (modals, `<pre>` blocks, ScrollStack) or Lenis eats its wheel events. Programmatic scrolling goes through `useSmoothScrollTo()`, not `scrollIntoView`. Disabled entirely under `prefers-reduced-motion`. `components/scroll-settings.tsx` exposes live glide / reach / smooth-wheel controls (persisted to `localStorage['scroll-prefs']`); prefs are pushed onto the running instance via `lenis.options`, never through the `options` prop — lenis/react re-creates the instance whenever that prop changes by value.
- **Theming**: `next-themes` class-based dark mode; Tailwind CSS variables; shadcn new-york, base color neutral.
- **Admin auth**: client stores a Worker-minted JWT in `sessionStorage`; requests to the Worker/artifact service carry `Authorization: Bearer <jwt>` via `authHeaders()`. Sign-in is Telegram OIDC or Google (invite-only, by verified email; same OAuth client as app.mncoleman.com).
- **Roles**: `super_admin` (owner, from `OWNER_SUB`/`OWNER_EMAIL`, never in KV) · `site_admin` (everything except users; legacy KV `role: 'admin'` means this) · `editor` (ticked `features` + per-artifact `artifactGrants`). Features are `artifacts`, `content` (posts, projects and resources), `library`, `analytics`, `rebuild`. The Worker re-reads the KV record on every request and gates routes by feature; every token it mints for the artifact service carries `artifacts: '*' | slug[]` and `manageSecrets`, and **the service is the enforcer** (fails closed on an absent claim) — the Worker streams multipart bodies it never parses. Only site admins and the owner change an artifact's visibility or password; private artifacts still need their password to open for everyone.
- **MCP OAuth** (`worker/mcp-oauth.ts`, selftest `npx tsx worker/mcp-oauth.selftest.ts`): `/oauth/*` is dispatched ABOVE the Origin/CSRF gate, so nothing in it may act on a cookie alone (the consent POST carries an HMAC bound to the session and the exact request). Tokens are signed with a key *derived* from `JWT_SECRET`, never `JWT_SECRET` itself, so an MCP token is not a panel session and the reverse. Redirect URIs are pinned to Claude's hosted callback and loopback. An MCP token reaches only the routes in `mcpRouteAllowed` (add a route there when adding a tool), never manages artifact secrets, and can only write post drafts whose Status follows the committed file. A grant in KV (`mcp:grant:<id>`) is one connected app; deleting it (admin Overview, Connected apps) is the kill switch.
- **Daily brief** (`/brief`, `docs/daily-brief.md`): the pages are static shells in the repo; editions are JSON in the `BRIEFS` KV namespace, written by the admin Worker (`/api/briefs/*`, validated by `lib/brief.ts`, selftest `npx tsx lib/brief.selftest.ts`) and read publicly by `worker-mcp` (`/api/brief/*`, including `/rss`). That split is deliberate: an edition can be hidden or deleted at once with no rebuild. `/brief/[date]` pre-renders a rolling window of dates because a static export cannot know which have an edition. `.brief` is a fixed full-screen layer that covers the site header on purpose, always dark, and uses plain labels (no "BLUF", no "Sector"). Edition text is plain text only and every source carries a URL. The MCP address bar moved from the top of the home page to the footer; `components/brief-callout.tsx` has its old slot.
- **Artifact edit mode + Claude link** (`server/src/artifact-collab.ts`, `components/admin/ArtifactEditMode.tsx`): instant HTML artifacts only. `/a/:slug?select=1` injects a postMessage select helper (ported from the Dovito hub); text edits and Claude's splice edits are sha-locked overwrites, no version history. "Link my Claude" mints a 2-hour, one-slug link token (revoked by deleting the `artifact_links` row) and a `sh` poll loop that long-polls `/api/link/:slug/next` (25s hold — under Bun's 60s `idleTimeout`). A link token is refused by `requireAuth` everywhere else.

## Common Tasks

- **Add a blog post**: `/admin/posts` -> New post. Edits autosave as a draft; **Publish** commits `data/posts/<slug>.md` through the Worker (`/api/posts/:slug/publish`) and the commit triggers the build. Do not also fire the deploy hook. `POST_DRAFTS` is bound in `worker/wrangler.toml`; if it is ever unbound, drafts answer 503 `drafts_unavailable` and the editor keeps edits in the browser only.
- **Worker routes the post editor depends on** (all need the `content` feature): `GET /api/users/names` (display names for the Author dropdown: first names only, never usernames or emails; an unnamed editor shows as "Editor"), `POST /api/citations/lookup` (reads a page's title/author/site/date for a citation; SSRF-guarded in `lib/citation-lookup.ts`, with a fake-fetch selftest), and `GET /api/posts?pending=1` (see Data Model). **Deploy the Worker before the site.**
- **Add a resource or project**: `/admin/projects` or `/admin/resources` → New → Publish. Publish commits `data/<collection>.json` through the Worker (`/api/collections/:name`, GET returns items + git sha, PUT requires that sha back and answers 409 if the file moved) and the commit triggers the Pages build. Do not also fire the deploy hook. `scripts/migrate-notion-collections.ts` is the one-off that seeded the files from Notion. Images pasted into the editor go to `public/collections/` via `POST /api/collections/images`.
- **Add an artifact (static)**: add an entry to `data/artifacts.json`; place the file under `public/artifacts/`. Dynamic artifacts are uploaded through the admin panel → Worker → artifact service.
- **Rebuild the Bible data**: only if the source texts change. `npx tsx scripts/bible/build.ts <sourceDir>` then `npx tsx scripts/bible/xrefs.ts <cross_references.txt>`, then `npx tsx scripts/bible/verify.ts`. The generated files are committed.
- **Add a page**: create `app/<route>/page.tsx`; add the nav link in `app/layout.tsx` (and to `components/mobile-nav.tsx` if needed); add it to `app/sitemap.ts`.
- **Add a shadcn/ui component**: `npx shadcn@latest add button` (shadcn) or `npx shadcn@latest add @react-bits/<name>` (ReactBits registry). Both registries are configured in `components.json`.
- **Change OG images**: edit `lib/og-card.tsx` (shared renderer) or a route's `opengraph-image.tsx`, **and make the matching change in `server/src/og.tsx`** so both pipelines still produce the same card. Bump `OG_VERSION` there so already-published instant artifacts re-render. `scripts/finalize-og-images.ts` runs at the end of the build: it gives each generated image a real `.png` sibling (Pages, like GitHub Pages before it, types files by extension, so extensionless images are rejected by strict OG consumers) and injects OG tags into the raw static artifact HTML, which Next never renders and which therefore ships without any.
- **Recapture `assets/og-veil.jpg`**: temporarily add `preserveDrawingBuffer: true` to the `new Renderer({...})` call in `components/ui/dark-veil.tsx` (OGL discards the buffer otherwise and `toDataURL` comes back black), load the site in dark mode, then read the canvas into a 1200×630 offscreen and POST the data URL somewhere that writes it to disk — never back through an agent's context. A backgrounded tab pauses rAF, so shim `requestAnimationFrame` onto `setTimeout` or the shader never draws a frame. Revert the renderer flag afterwards.
- **Deploy the Worker**: `cd worker && npx wrangler deploy` (secrets via `wrangler secret put`).
- **Change the version scheme**: it is CalVer, `YYYY.MM.DD.N`, assembled in `scripts/generate-build-info.ts`. `N` is the deployment's ordinal for the day and cannot be derived from the repository — a cron rebuild ships the same commit as the deploy before it — so the admin Worker keeps the counter in KV behind `POST /api/build/number`, guarded by the `BUILD_TOKEN` secret. The same value is a **secret build variable on the Pages project**, and the build reaches the Worker through `NEXT_PUBLIC_WORKER_URL`. `N = 0` means the counter was unreachable, which is how a local build looks and is deliberately distinguishable from a real first deploy.
- **Deploy the www redirect Worker**: `cd worker-www-redirect && npx wrangler deploy`.
- **Force a site rebuild** without a push: POST the Pages deploy hook (stored as the Worker secret `PAGES_DEPLOY_HOOK`), or use the admin panel's rebuild button, which does the same thing.
- **Deploy the MCP Worker**: `cd worker-mcp && npx wrangler deploy`, after `worker/` whenever both changed (its `ADMIN` service binding points at the admin Worker).
- **Deploy the token-count Worker**: `cd worker-tokens && npx wrangler deploy` (`ANTHROPIC_API_KEY` via `wrangler secret put`).
- **Deploy the artifact service**: see the Docker build/ship steps in `server/README.md`. Do NOT recreate the container from that `docker run` block by hand — carry the live container's env forward with `docker inspect artifacts --format '{{range .Config.Env}}{{println .}}{{end}}' | grep -v '^PATH='` instead, so a documentation drift can't silently drop a secret.

## Gotchas

1. **No basePath**: the site runs on the custom domain `mncoleman.com`, so `next.config.ts` has **no** `basePath`. (It previously used `/mncoleman`/`/matthew-coleman` for the GitHub Pages subpath — don't reintroduce that. `public/CNAME` is also gone; it only meant anything to GitHub Pages.)
2. **Notion token format**: tokens start with `ntn_`, **not** `secret_`. Validation checks for the placeholder `ntn_your_integration_token_here`.
3. **Notion sources**: the Resume page is the only runtime Notion source (the blog database is only read by the one-time import script). "Databases with multiple data sources are not supported" means you pointed at a database with synced/linked blocks — use the plain database ID.
4. **Content is build-time only**: Notion (resume) and git content changes need a rebuild to appear; they are not real-time. Use the admin rebuild trigger or wait for the daily cron.
5. **Images unoptimized**: static export disables Next image optimization; use `<img>` or `unoptimized` `<Image>`.
6. **Dark Veil canvas coverage**: use `position: fixed` with explicit `100vw/100vh`; use `window.innerWidth/innerHeight` (not parent dims) for resize; don't wrap the canvas in positioned containers; `overflow-x: hidden` on html/body; `resolutionScale` affects render resolution only, not visual size. WebGL/GSAP components need `'use client'`.
7. **Shared JWT secret**: the Worker and the artifact service share one HS256 `JWT_SECRET` (and `ARTIFACTS_JWT_SECRET`). Rotating one without the other breaks uploads.
8. **GA4 page_views are manual**: the root layout configures gtag with `send_page_view: false`, and `components/analytics.tsx` fires one `page_view` per App Router navigation. GA4 Enhanced Measurement's *"page changes based on browser history events"* must stay **OFF** on the property, or every soft navigation is counted twice. `/admin/analytics` reads GA4 through the Worker's `/api/analytics/summary` (service-account auth, `GA_SA_CLIENT_EMAIL` + `GA_SA_PRIVATE_KEY` secrets, `GA_PROPERTY_ID` var, 10-min KV cache).
9. **`profile-summary-card-output/`** is regenerated by CI daily — don't hand-edit the SVGs there.
10. **The two OG renderers must move together**: `lib/og-card.tsx` (static, build-time) and `server/src/og.tsx` (instant, runtime). Stored instant cards record an `ogVersion`; `/og/*` re-renders lazily when it no longer matches `OG_VERSION`, so a redesign reaches already-published artifacts instead of only new ones.
11. **Worker ↔ service role contract**: the admin Worker stamps a `role` claim on the short-lived artifacts JWT, and the service discloses decrypted private-artifact passwords only for `super_admin`. It **fails closed** — an absent claim omits the field. Consequence: deploy the Worker before the service, or the password column goes blank in between.
12. **No `btoa`/`atob` on the artifacts manifest.** `btoa` throws above U+00FF and `atob` decodes UTF-8 as Latin-1, so an em-dash in a description used to 500 the write *after* the file commit landed and corrupt the manifest on every edit. `worker/index.ts` has TextEncoder/TextDecoder base64 helpers — use those.
14. **A Pages custom domain needs a DNS record Cloudflare created.** Attaching the domain via the API does *not* create the record, and a record you made yourself first gives a permanent 522. Order that works: attach the custom domain to the Pages project, *then* point the record (proxied CNAME → `<project>.pages.dev`). Confirmed by rehearsing the whole cutover on a throwaway subdomain first — do that again before touching the apex.
15. **`_redirects` only matches the PATH.** A rule written against a full `https://www…` URL parses, ships, and silently never fires — which is exactly how the www redirect was missed the first time. Cross-hostname redirects need a zone Redirect Rule (needs a zone-scoped credential, dashboard only) or a Worker route, which is why `worker-www-redirect/` exists.
16. **Pages strips `.html`.** `/artifacts/foo.html` 308-redirects to `/artifacts/foo`. Content still serves and unfurlers follow it, so old shared links keep working — but the `og:url` values `finalize-og-images.ts` injects point at the `.html` form and are therefore redirect targets. Harmless; don't "fix" it by rewriting links.
17. **An empty `.env.local` fakes the resume.** Missing Notion credentials take the sample-data branch (resume only; a missing `data/posts/` fails a production build instead), so you get a clean green build that quietly published "Welcome to Notion CMS". If a build's output looks oddly generic, check the credentials before anything else. (This is also why the Pages project must keep its env vars — same trap, live.)
18. **Two wrangler credential files exist.** `~/.wrangler/config/default.toml` is the live one; `~/Library/Preferences/.wrangler/config/default.toml` can hold a stale token that fails with a misleading "Authentication error". Read the OAuth token from the former. It is short-lived (~1h) — run any `wrangler` command to refresh it before a long API session.
19. **Neither stored Cloudflare credential can edit Rulesets.** The 1Password DNS token does DNS + zone settings (it *can* flip the SSL mode); the wrangler OAuth login does Workers/Pages/DNS-adjacent work but only `zone:read`. Transform Rules, Redirect Rules and Page Rules therefore need Matthew in the dashboard. Don't conclude a token is broken — check this list first.

20. **Pages build watch paths: an empty `path_includes` matches NOTHING.** Setting `path_excludes` via the API without also setting `path_includes: ["*"]` silently filters out every push — deployments are created and then sit in `queued`/`idle` forever rather than failing. The pair is currently `path_includes: ["*"]` + `path_excludes: ["profile-summary-card-output/*"]`, so the daily profile-card commit no longer triggers a full Notion rebuild an hour before the cron does one. If a deploy ever hangs in `queued`, check these two fields first.

21. **The resume prints out of a stylesheet, not out of the DOM you see.** Nearly every element on `/resume` is invisible until JavaScript animates it in — motion's `initial={{opacity:0}}`, the contact chips' inline `animation: fadeSlideIn`, the experience cards' collapsed `grid-template-rows: 0fr`. A printer runs none of it, so the `@media print` block in `globals.css` is `!important` throughout (it is overriding inline styles) and scoped to `.resume-print`. It also has to **hide `[aria-hidden]` and un-hide `.sr-only`**, because the typewriter headings render half-typed decorative copy plus the real string. Verify it by injecting the rules as a plain stylesheet and screenshotting — **never by calling `window.print()`**, which opens a modal that freezes browser automation for the rest of the session.

22. **`public/_headers` matches trailing globs only.** `/_next/static/*` works; `/*/opengraph-image.png` needs a wildcard mid-path and would be the same silent no-op as gotcha #15. There is deliberately no rule for the generated OG cards.

23. **A rAF requested in a hidden tab never fires, and can pin a guard flag.** The `if (!raf) raf = requestAnimationFrame(...)` pattern used by the pencil is correct in a foreground tab and self-heals when a real tab is restored (Chrome delivers the pending callback), but anything that drives it programmatically while `document.visibilityState === 'hidden'` will pin `raf` non-zero and silently stop all further scheduling. This costs real time when verifying canvas work through browser automation — shim `requestAnimationFrame` onto `setTimeout` BEFORE dispatching the first synthetic event, not after. Related: gotcha in `chrome-hidden-tab-raf` memory.

24. **Read canvas pixels with `ctx.getImageData` on the live context.** Copying via `drawImage` onto a scratch canvas and sampling that returned all-clear on a canvas that demonstrably had ink on it, which sent a verification pass chasing a bug that did not exist. Sample the real context.

13. **Animation loops must be gated.** `components/ui/dark-veil.tsx` is the reference: `prefers-reduced-motion` renders one static frame, plus an IntersectionObserver and a `visibilitychange` pause, plus demand-driven rAF that stops once motion settles. `components/Waves.tsx` (the old light-mode backdrop, no longer mounted anywhere) followed it. Also keep `touchmove` listeners `passive: true` unless the handler genuinely calls `preventDefault()` — a non-passive one blocks every scroll frame on the page.
