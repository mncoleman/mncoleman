Two Findings That Shape Everything

Read before building

These two facts invalidate the obvious approach. Both were verified directly against live responses, and both cut against what a surface-level search returns.

Finding 01 Windsor PD runs its own dispatch — so it is invisible to every county feed

Windsor is a home-rule town with its own police department and its own dispatch center (970-674-6400 opt 1). It is not dispatched by Weld County and not by Larimer County. Consequence: there is no structured, machine-readable feed of Windsor police calls. Records come out only through JustFOIA / CORA. Your live Windsor-police option is scanner audio on FRCC talkgroup 1938 ("Local Law North") or nothing.

Verified four independent ways:

Decoy The "Windsor Police Incident Dashboard" is Windsor, Ontario

Searching for a Windsor police dashboard surfaces a polished ArcGIS app backed by a live, keyless FeatureServer with 38,761 records updated to today at 20:24 UTC. It looks perfect. It is Canada. Three independent giveaways:

# The tell-tale record sample:
2026-08-10 20:24 | Controlled Drug  | MCDOUGALL ST AT WYANDOTTE ST E
2026-08-10 19:34 | Assault          | 1600 BLOCK OUELLETTE AV
2026-08-10 19:07 | Mischief         | 700 BLOCK DOUGALL AV

# 1. Ouellette / Wyandotte / Dougall = Windsor, Ontario streets
# 2. spatialReference WKID 26917 = NAD83 UTM zone 17N
#    (Colorado is zone 13N — this is southern Ontario)
# 3. The owner's own snippet says "Windsor Police SERVICE" (Canadian usage)

I searched the full ArcGIS catalog and confirmed no Colorado equivalent exists. If another research pass hands you this dashboard, it is wrong.

Finding 02 State open-data portals lie about their freshness

data.colorado.gov reports "Crimes in Colorado" as updated 2026-08-10 (today) — but the newest actual record is 2024-12-31. The portal's updatedAt field tracks metadata touches, not data. This is precisely the stale-data trap that makes these datasets look usable when they aren't.

# ALWAYS run this before trusting any Socrata dataset:
curl "https://data.colorado.gov/resource/j6g4-gayk.json?\$select=max(incident_date)"

# Actual response:
#   [{"max_incident_date":"2024-12-31T00:00:00.000"}]
# Portal claimed: updated 2026-08-10. Reality: 19 months stale.

Tier 1 — Genuinely Live

Minutes old, verified

Sources that returned data measured in minutes when tested. This is where the dashboard's live map comes from.

Best source PulsePoint CAD feed — keyless, structured, 911-integrated

The strongest find. PulsePoint is wired directly into dispatch CAD systems. The public web app fetches JSON that is AES-encrypted client-side, but the passphrase is assembled in the open inside their JS bundle — so the feed is readable with no key, no account, and no rate limit encountered.

# Endpoint — returns {ct, iv, s}
# CryptoJS AES-CBC, OpenSSL EVP_BytesToKey (MD5) KDF
https://api.pulsepoint.org/v1/webapp?resource=incidents&agencyid=<ID>

# Passphrase (built at runtime from the string "CommonIncidents"):

Per incident you get CallReceivedDateTime, a type code (ME=medical, TC=traffic collision, PS=public service, ST=structure, HC=hazmat, IFT=interfacility transfer), FullDisplayAddress, lat/lon, and the responding unit roster. Buckets are active, recent (~24h), and alerts.

Two caveatsIt is fire/EMS dispatch — a crash, medical, or fire appears; a traffic stop or burglary does not. And PID185 was returning only active (1 call) with an empty recent bucket when tested, so poll it and build your own history rather than expecting backfill.

Official CDOT COtrip — authoritative and live for I-25. Free API key.

The best I-25 source: official CDOT Intelligent Transportation Systems data covering crashes, closures, and construction. Verified live — the endpoint returns 403 Not Authorized without a key, confirming the route is real and gated rather than dead.

# Register for a free key at https://manage-api.cotrip.org/  (returns 200)
curl "https://data.cotrip.org/api/v1/incidents?apiKey=$COTRIP_TOKEN"

# Paginate with &offset=<nextOffset>
# Reference implementation (Colorado's own emergency mgmt org):
#   github.com/dfpc-coe/etl-cotrip-incidents  -> task.ts
Don't bother with the GraphQL routemaps.cotrip.org/api/graphql responds but has introspection disabled and rejects guessed query names. The keyed REST API is the supported path — use it rather than reverse-engineering the map.

Windsor Windsor-specific alerting — low volume, but it is actually Windsor

NoCo Alerts via LETA (Larimer Emergency Telephone Authority). Windsor participates by intergovernmental agreement. leta911.org verified 200; nocoalerts.org redirects (302). This is the official emergency-notification channel for Windsor.

windsorpd.com CivicAlerts — press releases for significant incidents (recent items included an arrest for possession of explosives). Hours-to-days lag, but it is genuinely first-party Windsor PD and trivially scrapeable at windsorpd.com/CivicAlerts.aspx?CID=1.

Recommended Architecture

Build order
Plan Six layers, in build order
  1. Poll PulsePoint (PID185, 06945, 06960) every 60s. Dedupe on incident ID and persist — this is your live map and it builds the history the API won't backfill.
  2. Poll COtrip incidents every 2-5 min, filtered to an I-25 bounding box. Keep it a separate layer.
  3. Nightly scrape the Weld Daily Call Report for yesterday — the real police layer, and it lets you retroactively label Tier 1 incidents.
  4. Scrape windsorpd.com CivicAlerts daily — the only first-party Windsor PD channel that exists.
  5. If you want live Windsor police: verify TG 1938's encryption status, then run an RTL-SDR with trunk-recorder on FRCC and transcribe locally. This is the only path — and it also sidesteps the ToS issue below.
  6. Baselines from Tier 3, refreshed quarterly.
Steps 1-4 and 6 are all first-party or officially sanctioned.Step 5 is the only one with friction, and running your own receiver removes even that.

Legal & Terms of Service

Flagged, not cleared
Read first Where the friction actually is

Receiving unencrypted public safety radio is legal in Colorado. The friction is contractual, not statutory.

BroadcastifyTheir ToS restricts re-transmission and automated scraping, and archives/Calls are paid tiers. Running your own SDR receiver avoids this entirely — that is your own lawful reception, not their stream.
PulsePoint — ToS not reviewedFlagging rather than clearing this one. The data is published for public consumption, but the payload is deliberately obfuscated, and extracting the passphrase to read it is a fact worth weighing before anything public-facing. Fine for personal use; read their terms before shipping it to others.

weld.gov, data.colorado.gov, api.weather.gov, and COtrip (with a registered key) are all intended for public/programmatic access. Be polite with poll rates.
